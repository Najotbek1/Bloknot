# Maqsad (formerly Bloknot) — notes for Claude

- The app's visible name is **Maqsad**; internal names stay `bloknot` (IndexedDB name, `.bloknot` files, code). Never change `applicationId` `uz.najotbek.bloknot`: installed apps would lose their data.

- The user speaks Uzbek: reply in Uzbek. UI text lives only in `src/i18n/`: `uz.ts` is the source, and `en ru de ja ko hi ar` mirror its keys (TypeScript `Messages` type + `languages.test.ts` check keys and placeholders). Every new key goes into all eight files. Use `t()` (ICU-style `{count, plural, …}` is supported); dates and weekday names come from `src/i18n/format.ts` (Intl for non-Uzbek), never hard-coded. Arabic is RTL: use logical CSS properties (`inline-start/end`), not left/right.
- Plan and stage list: `docs/REJA.md`. Work stage by stage; update that file when a stage is finished or the plan changes.
- Stack: React + TypeScript + Vite, Capacitor (Android), Electron for Windows/macOS/Linux (`desktop/`: `main.cjs` serves the built `dist/` as `app://maqsad/`, keeps running in the tray, shows notifications from the plan the web app sends; `preload.cjs` exposes `window.maqsadDesktop`, typed in `src/platform/desktop.ts`). CI job `desktop` is a matrix: windows-latest → unsigned NSIS `maqsad-windows`, ubuntu-latest → AppImage + deb `maqsad-linux`, macos-latest → ad-hoc-signed x64/arm64 dmg `maqsad-mac` (no Apple account yet: first open needs "Open Anyway"). The same Windows job also builds a Microsoft Store `.appx` (`maqsad-msstore`, uploaded only when the Variables `MSSTORE_IDENTITY_NAME`/`MSSTORE_PUBLISHER`/`MSSTORE_PUBLISHER_NAME` from Partner Center are set; tiles in `desktop/build/appx/` from `scripts/render-store.mjs`); in a Store install (`process.windowsStore`, `DesktopApi.isStore`) the app cannot set its own autostart. Platform differences live in `main.cjs` (`IS_MAC`/`IS_LINUX`: Mac keeps an app/edit menu, Linux autostart is `~/.config/autostart/maqsad.desktop`) and in texts chosen by `desktop.platform`; the installer version comes from the root `package.json`. Main-process text comes from the web app via `setLabels` (i18n rule still applies). No server: all data is local (IndexedDB).
- Layout: `src/core` (pure logic, must have Vitest tests), `src/platform` (Capacitor/Electron/browser differences behind one interface), `src/features/<name>`, `src/ui` (shared components, `theme.css` tokens).
- Every stored record has `id` (UUID), `createdAt`, `updatedAt`, `deletedAt` (soft delete) so export/import can merge by last write. Every DB schema change needs a new Dexie version + migration.
- No Android SDK in the container: APKs are built by `.github/workflows/build.yml`. Before pushing run `npm run lint && npm test && npm run build && npm run e2e`, and check UI with Playwright at 390×844 (light + dark).
- `e2e/` smoke tests run against the build in two projects; `new-webview` makes `scrollTo` return a Promise like recent Android WebView. Never write an expression-bodied effect (`useEffect(() => fn())`): whatever `fn` returns becomes the cleanup and crashed the app on Android 16. Use braces.
- The AdMob banner is a native view drawn over the WebView: anything that covers the screen (sheets, full-screen editors, the keyboard) must hold `pushAdBlocker()` while open. Real ad IDs come only from the GitHub repository Variables `ADMOB_APP_ID` / `ADMOB_BANNER_ID` (CI → `VITE_ADMOB_*` for `src/platform/adConfig.ts`, `ADMOB_APP_ID` → Gradle `resValue admob_app_id`); without them Google's test IDs are used. The owner sets them alone (`docs/ADMOB.md`); never hard-code real IDs. A third, `ADMOB_APP_OPEN_ID`, drives the full-screen App Open ad, whose limits live in `src/core/ads/appOpenPolicy.ts` (≥3 days after install, ≤5 a day at least 60 min apart, cold start or ≥30 min away; never over a ringing alarm, a notification tap or an open sheet). These limits are the owner's decision; don't raise them.
- Wi-Fi sync (`src/core/sync/lan.ts`): the Windows app runs a one-off local http server (`desktop/main.cjs`, relay only) and shows a QR code with its address and an AES-GCM key; the phone scans it (Google code scanner, no camera permission) and posts via `CapacitorHttp` (Android allows cleartext for this; the payload is encrypted). Both sides merge with `importBackup`, so new tables reach sync through the backup. The desktop app has no ads (owner's decision: AdMob is mobile-only, AdSense is banned in apps).
- Wide layout (computer-sized window, ≥ 960px: the Windows app and the website on a big screen): CSS `@media (min-width: 960px)` blocks next to each component's phone styles, plus `useWideLayout()` (`src/ui/useWideLayout.ts`) where the structure differs (notebook list beside the open note). The same `nav.bottom-nav` becomes the side menu; `.columns` puts two column children side by side; sheets become centred dialogs; the Fab shows its label. The phone layout must stay unchanged. Keyboard: Ctrl+N clicks the screen's `.fab`, Ctrl+1…5 switch tabs. The alarm button is hidden when `isDesktop`.
- Manual order: `Task.order` (new tasks get their creation time, so they land last); `reorderTasks` (`src/core/db/tasks.ts`) renumbers a list 0…n-1 with new `updatedAt`. `TaskRows sortable` shows the ⋮⋮ grip (pointer drag + ↑/↓). Focus timer: `src/core/focus.ts` (pure) + `src/features/focus/` (one session in `localStorage` `maqsad.focus`, per device, not synced); its "time is up" notification is appended to the notification plan with fixed id 99999 by `useNotificationSync`.
- Themes: every colour is a token in `src/ui/theme.css`; a new theme is one `:root[data-theme=x], [data-preview=x]` block defining every `--color-*` / `--chart-*` token, plus the `ThemePreference` value and its label. Components never hard-code colours.
- The "coach" (`src/core/coach.ts`) words notifications by the 7-day responsibility score: < 50 strict, 50–70 neutral, > 70 inspiring. Strict phrases must stay firm but never insult the user (owner's decision).
- Dexie schema is at version 3 (`dayReminders`, `alarms`). New tables must also be added to the backup (`src/core/sync/backup.ts` `TABLES`, `readAll`, `parseBackup`, `importBackup`), tolerating files that lack them.
- The alarm clock is our own native plugin (`android/app/src/main/java/uz/najotbek/bloknot/alarm/`, registered in `MainActivity`), bridged by `src/platform/alarm.ts`; the web app plans the next week of rings (`src/core/alarms/schedule.ts`) and the native side stores them for reboots. Java is only compiled in CI: check the Android job after every change there. A ringing alarm must stop only through the typed text (owner's decision: no snooze, no dismiss button).
- The owner's handbook (no-code tasks: APKs, AdMob, Play, versions) is `docs/QOLLANMA.md`; keep it in step with the build.
- Bump `version` in `package.json` with each user-facing change; it is shown in Settings and in the crash screen. The owner reset it to 0.x (0.5.0) until the Play launch; Android updates follow `versionCode` (the CI run number), so a lower name still installs over a higher one.
- `android/app/bloknot-dev.keystore` is a deliberately public dev key so CI builds update each other; never use it for a Play release. The Play upload key exists only in GitHub Secrets (`RELEASE_*`); `*.jks` is git-ignored — never commit one. Play materials are in `docs/play/`; icon source `docs/brand/maqsad-icon.svg` → `node scripts/render-brand.mjs`.
